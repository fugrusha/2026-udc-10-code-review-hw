# Task E (bonus)

## Шлях 1 — пайплайн по-справжньому

- **Форк і PR, на якому запустився workflow:**
  <https://github.com/fugrusha/2026-udc-10-code-review-hw/pull/1>
  (`pipeline/ai-review.yml` скопійовано в `.github/workflows/ai-review.yml` на
  `main` цього форку; PR відтворює `review-queue/pr-1` — найменший диф із черги —
  гілкою `demo/pr-1-pagination` проти `main`.)

- **Коментар бота:** job `ai-review` відпрацював і запостив коментар, але текст у
  ньому — заглушка:

  > 🤖 AI review — advisory only, not a required check
  >
  > (no response text — see workflow logs)

  Причина — не в пайплайні, а в акаунті Anthropic за `ANTHROPIC_API_KEY`
  (детальніше нижче). Лог виклику API (видимий лише учасникам репо, не в
  коментарі) показує справжню відповідь API:

  > `{"type":"error","error":{"type":"invalid_request_error","message":"Your credit
  > balance is too low to access the Anthropic API. Please go to Plans & Billing to
  > upgrade or purchase credits."}}`

  Обидва job-и (`tests` і `ai-review`) завершились успішно — вся логіка пайплайна
  (побудова дифу, промпт, виклик API, постановка коментаря через `gh pr comment`)
  відпрацювала коректно; впала лише сама модель-відповідь через брак кредитів на
  акаунті. Зупинились тут свідомо, не поповнюючи акаунт грошима заради дорогого
  рядка в домашньому завданні — пряме пояснення залишено коментарем на самому PR.

- **Що пішло не так і як полагодили:** цей прогін на справжньому GitHub Actions
  спіймав **два реальні баги в пайплайні**, яких не було видно при самому лише
  читанні `pipeline/ai-review.yml`, плюс одну проблему акаунту:

  1. **Умова пропуску для форків була хибною.**
     `if: ${{ !github.event.pull_request.head.repo.fork }}` пропускала
     `ai-review` навіть для PR **усередині того самого форку** — бо
     `head.repo.fork` означає «цей репозиторій сам є форком чогось», а не
     «цей PR прийшов з іншого репозиторію». Перший прогін показав job `ai-review`
     пропущеним (`0s`), хоча PR не був «зовнішнім». Полагоджено порівнянням
     `head.repo.full_name` із `github.repository` — це і є справжня ознака
     PR від стороннього контриб'ютора, яку треба було перевіряти для безпеки
     секрету.
  2. **`docs/review-standard.md` був відсутній на `main`.** Стандарт рев'ю
     існував лише на гілці домашнього завдання (`ws10/holovko`), а job читає
     його з того, що є у чекауті на момент прогону. Другий прогін впав на
     `cat: docs/review-standard.md: No such file or directory`. Полагоджено:
     саме стандарт — це конфіг, від якого залежить пайплайн, тож він має жити
     на базовій гілці так само, як і сам workflow-файл.
  3. **Помилки API мовчки ковталися** — `jq`-фолбек `// "(no response text...)"`
     не падав і не лишав сліду, чому саме відповіді немає. Додано рядок, що
     логує сиру відповідь API в лог job-а (не в коментар PR) — наступного разу
     причина видно одразу, а не вимагає здогадок.
  4. **Акаунт:** перший реальний виклик API впав з
     `"This API key is not scoped to a workspace"` — полагоджено заміною ключа
     на прив'язаний до workspace. Другий виклик упав уже з браком кредитів —
     це зовнішнє обмеження акаунту, не дефект пайплайна; вирішили задокументувати
     чесно, а не докуповувати кредити заради рядка в домашньому завданні.

  Усі чотири виправлення з пунктів 1–3 унесено в `pipeline/ai-review.yml` у
  цьому репо (не лише у форку) — отже, сам факт запуску «по-справжньому» зробив
  пайплайн із Task D коректнішим, ніж він був до цього прогону.
